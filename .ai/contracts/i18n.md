# UI translation contract (i18n)

Status: **Implemented** (`apps/neurofeed-egui/src/i18n.rs`, `apps/neurofeed-egui/locales/*.ftl`).

- One Fluent file per language, compiled in: `locales/en.ftl` (source and
  fallback), `locales/de.ftl`. Add a language: new `.ftl`, add it to
  `i18n::LOCALES` and to `nf_core::settings::Language`.
- UI code never hard-codes user-visible English: use `t!("key")` or
  `t!("key", name = value)` (Fluent `{ $name }`). Keys are
  `<ui-file>-<slug>`; navigation labels use `ui::view_label(view)`
  (`view-*`), Settings section/card titles `settings-card-<slug>`.
- Setting `settings.language` = `auto` (default, system locale via
  `sys-locale`, English when unsupported) | `en` | `de`; via
  `settings.set {"language":"de"}` (MCP / CLI) or Settings → General → Language.
- Missing key in a locale → English; unknown key → the key itself.
- Tests (`i18n::tests`): every key exists in every locale, every `.ftl`
  parses, every `t!("…")` key used in `src/` exists in `en.ftl`.
- Not translated (yet): formatted strings that still use `format!` with
  numbers (≈130, e.g. history/trust/streaming details), protocol titles and
  descriptions from `nf-core`, MCP/CLI output (always English).
