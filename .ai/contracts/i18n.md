# UI translation contract (i18n)

Status: **Implemented** (`apps/neurofeed-egui/src/i18n.rs`, `apps/neurofeed-egui/locales/*.ftl`).

- One Fluent file per language, compiled in: `locales/en.ftl` (source and
  fallback), `locales/de.ftl`. Add a language: new `.ftl`, add it to
  `i18n::LOCALES` and to `nf_core::settings::Language`.
- UI code never hard-codes user-visible English: use `t!("key")` or
  `t!("key", name = value)` (Fluent `{ $name }`). Keys are
  `<ui-file>-<slug>`; navigation labels use `ui::view_label(view)`
  (`view-*`), Settings section/card titles `settings-card-<slug>`.
- Setting `settings.language` = `auto` (default, system locale via
  `sys-locale`, English when unsupported) | `en` | `de`; via
  `settings.set {"language":"de"}` (MCP / CLI) or Settings → General → Language.
- Missing key in a locale → English; unknown key → the key itself.
- Tests (`i18n::tests`): every key exists in every locale, every `.ftl`
  parses, every `t!("…")` key used in `src/` exists in `en.ftl`.
- Formatted strings use Fluent variables, never `format!` around English:
  `t!("history-n-selected", n = n)`. Pre-format decimals in Rust
  (`pct = format!("{:.0}", x)`) so both locales show the same precision;
  pass integers as numbers so plurals (`{ $n -> [one] … *[other] … }`) work.
  Keep separators like ` · ` in code, not at the edge of a Fluent value
  (Fluent trims leading/trailing spaces).
- Built-in protocol titles/summaries: `i18n::protocol_title(p)` /
  `protocol_summary(p)` look up `protocol-<kebab-id>-title|summary`
  (e.g. `protocol-rest-awake-title`); custom protocols show the user's text.
  The protocol `id` and English `title`/`summary` in `nf-core` are unchanged
  (MCP / CLI / saved sessions). Test `builtin_protocols_translated`.
- Small lookup tables (sound choices, builder features) store Fluent keys and
  call `i18n::tr(key, &[])` at draw time.
- Intentionally English:
  - MCP / CLI output and the agent bridge: JSON keys and values, tool
    descriptions, error texts (agents and scripts depend on them).
  - Reasons and messages produced in `nf-core` and shown verbatim in the UI
    (`session.enabled()` disabled reasons, pause/held-back/dirty reason
    codes, AI model descriptions/guides, nerd-sheet pile titles, import
    warnings, device-lost reasons, store/export low-level errors). They are
    shared with MCP; translating them needs reason codes in core first.
  - Units, channel names, device models (Muse, Crown), format names (EDF,
    OSC, LSL, PSD, SpO2), paths, MIME types, plot axis numbers.
  - Settings search terms (English + translated title are both searched).
